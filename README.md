# تطبيق مسجد الخير — Flutter

تطبيق الجوال للبوابة التعليمية لمسجد الخير. يتصل بخادم الـ API الخاص بالموقع
(`/api/v1`) ويحترم صلاحيات كل دور كما هي في الباك إند.

## المتطلبات

- Flutter 3.35 أو أحدث (يُنصح بالقناة `stable`)
- خادم Laravel يعمل من فرع `feature/mobile-api-v1`:

```bash
php artisan serve --host=0.0.0.0 --port=8000
```

## إعداد عنوان الخادم

الافتراضي هو خادم الإنتاج للموقع:

```
https://www.alkheir-mosque.com/api/v1
```

يمكن تغيير العنوان في أي وقت من شاشة الدخول (زر الخادم أعلى الشاشة)، ويُقبل
إدخال الجذر أو العنوان كاملاً مع `/api/v1` فيُنظَّف تلقائياً. للتطوير المحلي:

| المنصة | عنوان التطوير |
| --- | --- |
| Android Emulator | `http://10.0.2.2:8000` |
| المتصفح / iOS Simulator | `http://127.0.0.1:8000` |
| جهاز فعلي | عنوان الكمبيوتر على الشبكة، مثل `http://192.168.1.20:8000` |

ولتثبيت عنوان ثابت عند البناء:

```bash
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

> **ملاحظة مهمة:** اختبار الإنتاج أظهر أن `https://www.alkheir-mosque.com/api/v1/...`
> يرد حالياً بـ 404، أي أن واجهة الجوال من فرع `feature/mobile-api-v1` لم تُنشر بعد على
> الخادم. يجب نشر الفرع على الإنتاج حتى يعمل تسجيل الدخول؛ حتى ذلك الحين يعرض
> التطبيق رسالة توضح ذلك بدل خطأ عام.

## التشغيل

```bash
flutter pub get
flutter run
```

للمتصفح (مفيد لمراجعة الواجهة):

```bash
flutter run -d chrome
```

## اللغة والمظهر

- اللغة الافتراضية العربية (RTL)، ويمكن التبديل إلى الإنجليزية (LTR) من شاشة الدخول
  أو من قائمة الحساب. يُحفظ الاختيار محلياً.
- المظهر فاتح/داكن بألوان الهوية (أخضر الجامع وذهبي) وخط Dubai نفسه المستخدم في الموقع.
- النصوص العربية تُترجم عبر `tr()` / `trf()` من `lib/core/i18n/`. المفتاح هو النص العربي نفسه،
  والترجمة الإنجليزية في `lib/core/i18n/en_dictionary.dart`.

**عند إضافة نص جديد:** اكتبه بالعربية داخل `tr('...')` وأضف ترجمته إلى القاموس.
اختبار `test/i18n_test.dart` يفشل تلقائياً إذا نسيت الترجمة.

## الصلاحيات

- كل شاشة تُظهر أو تخفي عناصرها حسب صلاحيات المستخدم القادمة من `/api/v1/auth/token`
  (أسماء الصلاحيات في `lib/core/rbac/permissions.dart` مطابقة لأسماء الباك إند).
- ولي الأمر يرى بوابة الأسرة (`/api/v1/parent/*`)، والطاقم يرى الشاشات الإدارية.
- الخادم هو المرجع الأخير: أي طلب مرفوض يعرض رسالة الخادم بلغة المستخدم.

## وحدات الإدارة المنفّذة

تظهر داخل تبويب **الإدارة**. كل وحدة تظهر فقط إذا وُجدت صلاحيتها في استجابة
تسجيل الدخول (`user.permissions`)، ولا تُقرأ أسماء الأدوار هنا (`ModuleAccess` في
`lib/core/rbac/module_access.dart`):

| الوحدة | الصلاحيات | ما تفعله |
| --- | --- | --- |
| المالية | `finance.reports.view` أو `finance.cash-box.view`، `finance.cash-box.adjust`، `finance.cash-box.transfer`، `finance.exchange.view/create`، صلاحيات `*-requests.view` | الملخص والصناديق والسجل، تسوية يدوية، تحويل، صرف عملة، عرض الطلبات |
| الأولياء | `parents.view/create/update/delete` | بحث وتفاصيل، إضافة وتعديل وحذف |
| المعلمون | `teachers.view/create/update/delete` | بحث وتفاصيل، إضافة وتعديل وحذف، مع حساب الدخول |
| الكورسات | `courses.view/create/update/delete` | تصفية بالحالة، إضافة وتعديل، إنهاء وإعادة تفعيل |
| جداول الحلقات | `groups.view` و`group-schedules.manage` | عرض الحصص وإضافتها وتعديلها وحذفها |
| اختبارات القرآن | `quran-partial-tests.*` و`quran-final-tests.*` | دورات الطالب، بدء دورة بالأجزاء المؤهلة، تسجيل المحاولات |
| ملفات الطلاب | `students.view`، `students.files.manage`، `students.photo.update` | تقدّم الطالب، الصورة (عرض/تحديث/حذف)، المرفقات (رفع/تنزيل/حذف) |
| الطلاب والتسجيلات | `students.create/update/delete`، `enrollments.view/create/update/delete` | دليل الطلاب مع الإضافة والتعديل والحذف، وتسجيلات الطلاب في الحلقات |
| الحلقات | `groups.view/create/update/delete` | إنشاء الحلقات وتعديلها باختيار الكورس والسنة والمعلم والصف من قوائم |
| حضور الطلاب | `attendance.student.view`، `attendance.student.take`، `attendance.student.toggle-day-status` | أيام الحضور، فتح اليوم وإغلاقه، وأخذ حضور حلقة كاملة |
| حضور المعلمين | `attendance.teacher.view` و`attendance.teacher.take` | أيام حضور المعلمين، وتسجيل حضور يوم لجميع المعلمين النشطين |
| الحفظ | `memorization.view` و`memorization.record` | سجل الحفظ والمراجعة، وتسجيل صفحات لتسجيل نشط (مع كشف الصفحات المكررة) |
| اختبارات الأوقاف | `quran-awqaf-tests.view/record` أو `quran-tests.view/record` | قائمة الاختبارات وتسجيل اختبار بالجزء والنوع والنتيجة |
| النقاط | `points.view`، `points.create-manual`، `points.void` | سجل النقاط، نقاط يدوية موجبة أو سالبة، وإلغاء القيد |
| التقييمات | `assessments.view` و`assessment-results.record` و`assessment-results.record-scores` | التقييمات وتفاصيلها، وتسجيل النتائج |
| ملاحظات الطلاب | `student-notes.view/create/update/delete` | الملاحظات حسب الرؤية، والإضافة والتعديل والحذف لمن يملك الصلاحية ولملاحظاته |
| المناهج | `curricula.manage` أو `curricula.record` | المنهج ومواده ودروسه، وتقدّم المنهج لكل حلقة، وتنزيل ملفات PDF |
| الأنشطة | `activities.view` و`activities.finance.view` و`activities.registrations/payments/expenses.manage` | تسجيل المشاركين، ودفعات النشاط، ومصروفاته |
| الفواتير | `invoices.view/update`، `payments.view/create/void` | بنود الفاتورة، ودفعاتها، وإلغاء الدفعات، وقائمة المدفوعات |
| التقارير | `reports.view` | نظرة عامة بالفلاتر، وملخص المعلمين اليومي |
| حسابي | لكل حساب مسجّل | البيانات، اسم المستخدم (إن كان قابلاً للتعديل)، الصورة، كلمة المرور، الخروج من كل الأجهزة |

الحسابات التي لا تملك أي دور إشرافي لكنها تملك صلاحية وحدة تظهر لها تبويب الإدارة
وحده. الخادم يبقى المرجع: أي رفض يعرض رسالته بلغة المستخدم.

عند فتح التطبيق يُحدَّث الحساب من `GET /api/v1/bootstrap` (الصلاحيات والمؤسسة والميزات)،
ويُستخدم `GET /api/v1/dashboard` لعرض المؤشرات في أعلى تبويب الإدارة حسب الصلاحيات.

## ما تبقّى

- **المالية:** شاشة المالية تعرض الصناديق والسجل والتحويلات والصرف والطلبات. مدفوعات الأنشطة
  والفواتير في شاشتي الأنشطة والفواتير. لا توجد إنشاء أو مراجعة لطلبات السحب/المصروف/الإيراد
  (الطلبات للعرض فقط)، ولا طباعة أو تصدير.
- **الأولياء والمعلمون:** إدارة الأدوار والصلاحيات المباشرة ونطاق الوصول، وصور المعلمين،
  والتوقيعات المالية، وقرارات الاعتماد، كلها للموقع فقط في الإصدار الأول حسب `docs/api.md`.
- **الكورسات:** جدولة الكورس ونسخه خارج المرحلة الثالثة حسب `docs/api.md`.
- **الحضور:** إدخال حضور عبر الباركود (`scan`/`quick-scan`) ما زال في شاشة المسح القديمة.
- **الحفظ:** نوع `correction` يُعرض في السجل فقط، لأن الإنشاء يقبل `new` و`review` كما في الخادم.
- **التقييمات:** لا توجد إضافة لتقييم جديد (الخادم لا يوفّر إنشاء التقييمات)، والنتيجة تُسجَّل لطالب واحد في كل مرة.
- **المناهج:** العرض والتنزيل فقط؛ لا تسجيل لتقدّم الدروس من الهاتف.
- **اختبارات القرآن:** لا توجد قائمة عامة لكل الدورات الجزئية والنهائية؛ تُفتح من ملف الطالب فقط.
  أسماء حالات المقاطع غير المعروفة تُعرض كما يرسلها الخادم.
- **المرفقات:** نوع الملف حقل نصي حر، ولا توجد معاينة داخل التطبيق.
- **الصورة:** بلا قص أو ضغط على الجهاز؛ الحد الأقصى يفرضه الخادم.
- **لم يُختبر على أجهزة حقيقية:** التحقق الحالي يشمل `flutter analyze` و`flutter test`
  و`flutter build web --release` فقط. بناء Android وiOS وWindows لم يُجرَّب مع الحزم الجديدة
  (`file_picker`، `open_filex`، `path_provider`).
- **الاختبارات:** تغطي النماذج والصلاحيات واختبار الترجمة. لا توجد اختبارات واجهات ولا
  استدعاءات حيّة للخادم؛ بيانات النماذج مأخوذة من وحدات التحكم في الباك إند.
- **النشر:** الواجهة تحتاج أن يكون فرع `feature/mobile-api-v1` منشوراً على الخادم؛ حتى ذلك
  الحين يرد `/api/v1/*` بـ 404.

## التحقق من نشر الواجهة

```bash
curl -i https://www.alkheir-mosque.com/api/v1/bootstrap
```

الاستجابة الصحيحة بعد النشر هي `401` (غير مسجّل الدخول). الاستجابة `404` تعني أن الفرع
لم يُنشر بعد.

## ملاحظات المنصات

- **Windows:** بناء التطبيق مع الإضافات يتطلب تفعيل *Developer Mode* (روابط رمزية)،
  وإلا يفشل `flutter pub get` أو البناء برسالة `Building with plugins requires symlink support`.
- **تنزيل الملفات:** على الهاتف يُحفظ الملف مؤقتاً ثم يُفتح بتطبيق النظام، وعلى الويب
  يُطلق المتصفح تنزيلاً عادياً (`lib/core/files/`).

## حدود معروفة

- النص الذي يحوي متغيرات يُكتب بـ `trf('... {0} ...', [قيمة])` وليس بتسلسل `$` داخل
  النص العربي، حتى تبقى ترجمته سليمة. اختبار التغطية يتحقق من النصوص الثابتة فقط.
- تخزين رمز الدخول الحالي في SharedPreferences؛ يُنصح بالانتقال إلى التخزين الآمن
  (flutter_secure_storage) قبل النشر.
